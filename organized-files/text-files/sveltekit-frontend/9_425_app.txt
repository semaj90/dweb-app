A. Important concepts & knobs for RTX 3060 Ti (8 GB)

Model size: 13B+ models won’t fit. Prefer small/medium models or quantized versions (q4_k_m / q4_0 / q8). Use embedding models built for small VRAM (nomic-embed-text, bge-small-e/384-dim etc.). Generator models must be chosen to fit (or use streaming & offload).

Quantization: use GGUF 4-bit quant (q4_k_m / q4_0) or 8-bit to dramatically reduce VRAM. llama.cpp / GGML quantization helps.

FP16 / BF16: Use fp16 where supported. On 8GB, 16-bit helps but quantization is often required.

Offloading: CPU offload for KV cache or layers (llama.cpp / ggml have some support). Some frameworks support device_map + offload (hf accelerate + bitsandbytes).

Batching & Async: batch small queries when possible; use prefetching.

Flash attention / kernels: enable flash attention if your stack supports it (faster, lower memory), but verify Ollama/llama.cpp build + GPU drivers.

TensorRT: for production speed, convert model to TensorRT engine (Trton or TensorRT-LLM). That often requires more engineering and may not be possible for all models.

Queue + Worker: always use a job queue so requests don’t hang waiting for GPU.

Monitoring: track VRAM usage, latency, queue depth, failure rate.

GPU tuning: set CUDA_VISIBLE_DEVICES, control num_threads, set NVIDIA_TF32_OVERRIDE? (driver dependent). For Ollama: environment flags like OLLAMA_FLASH_ATTENTION, OLLAMA_NUM_PARALLEL, OLLAMA_MAX_QUEUE, and OLLAMA_LOAD_TIMEOUT are useful.

# worker/gpu_worker.py (concept)
import os, json, time, pika, torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from accelerate import init_empty_weights, load_checkpoint_and_dispatch

AMQP_URL = os.getenv("AMQP_URL", "amqp://guest:guest@localhost:5672/")
MODEL_NAME = os.getenv("MODEL", "your/quantized-gguf-or-hf-repo")
DEVICE = "cuda" if torch.cuda.is_available() else "cpu"

# Simple loader with bitsandbytes 8-bit
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    load_in_8bit=True,         # requires bitsandbytes
    device_map="auto"          # accelerate will place layers on device
)

def on_message(ch, method, props, body):
    msg = json.loads(body)
    # chat generation logic — build prompt + RAG context
    prompt = msg["prompt"]
    inputs = tokenizer(prompt, return_tensors="pt").to(DEVICE)
    with torch.no_grad():
        out = model.generate(**inputs, max_new_tokens=256)
    text = tokenizer.decode(out[0], skip_special_tokens=True)
    # Persist to Postgres (call API or write to DB)
    # Publish event to x.events for streaming status
    ch.basic_ack(delivery_tag=method.delivery_tag)

# AMQP setup
params = pika.URLParameters(AMQP_URL)
conn = pika.BlockingConnection(params)
ch = conn.channel()
ch.exchange_declare('x.events', 'fanout', durable=True)
ch.queue_declare('q.chat.generate', durable=True)
ch.basic_consume('q.chat.generate', on_message)
ch.start_consuming()


Notes & knobs

Use load_in_8bit=True requires bitsandbytes + proper CUDA + fused kernels.

Use device_map="auto" or use dispatch_config from accelerate to avoid OOM.

For embeddings, use sentence-transformers or Ollama /api/embeddings (fast).

Use a prefetch_count=1 or small number; rely on multiple worker instances for concurrency.

Use batching by collecting several messages for a short window (10-30ms) and run them together if your model supports batched generation.

  -- Find contextually relevant past conversations

    prompt, response, metadata,
    embedding <-> $current_embedding as similarity,
    CASE
      WHEN metadata->>'user_satisfaction' = '5' THEN 1.2
      WHEN metadata->>'user_satisfaction' = '4' THEN 1.0
      WHEN metadata->>'user_satisfaction' = '3' THEN 0.8
      ELSE 0.5
    END as rl_weight
  FROM ai_history
  WHERE user_id = $user_id
    AND embedding <-> $current_embedding < 0.3
  ORDER BY (embedding <-> $current_embedding) * rl_weight
  LIMIT 5;
